# 候物 iOS v1.0.6 更新优化说明

发布日期：2026-08-04

## 1. 对话结论

本版本根据 UI 优化讨论整理，目标是让「候物」从单纯的心愿记录列表，更明确地成为一个帮助用户判断购买优先级、跟进预算和存钱进度的决策工具。

### 1.1 首页方向

- 顶部继续保留状态筛选，但用筛选芯片和数量统计表达「想买 / 已拥有 / 放下 / 全部」，减少传统 Tab 带来的层级割裂。
- 候物卡片需要有清楚的信息顺序：价格和商品名称优先，其次是已存 / 目标金额，再用进度条和百分比表达距离目标的程度。
- 进度颜色使用语义化区间：0%–30% 为中性灰，30%–70% 为橙色，70% 以上为绿色，完成后使用冷静的蓝灰色。
- 高 / 中 / 低优先级使用红 / 橙 / 灰的颜色语义，并保留轻量标签，不让标签抢过价格和进度。
- 卡片操作统一收敛到右侧更多菜单；底部保留批量整理和浮动新增入口，减少操作分散。
- 增加统计入口，展示总预算、已存金额、完成率和分类分布，让用户能快速看到整体消费计划。

### 1.2 新增流程方向

新增页按参考设计改为四步引导：选择类型、填写基础信息、设置预算与分类、确认信息。当前数据模型尚未包含商品图片字段，因此本版使用按类型和分类变化的图标缩略位，真实图片保存和链接自动解析继续作为后续数据模型升级项。

### 1.3 本地提醒方向

- 提醒完全使用 iOS 本地通知，不依赖账号、服务器或网络，参考 LightKitList 的权限申请、确定性通知 ID、前台展示和启动同步方式实现。
- 只在用户主动开启提醒时申请系统通知权限；提醒日期和时间可在新增 / 编辑流程中设置。
- 提醒文案根据候物信息自动组合名称、目标价格、已存金额、剩余金额、存钱进度、优先级和分类；信息不足时自动使用更简洁的决策提示。
- 编辑候物会覆盖旧提醒；关闭提醒、移入回收站、标记为已拥有或放下时会取消提醒；App 启动时只重建仍然有效的提醒。

### 1.4 设置页方向

- 设置页由大块卡片调整为更接近 iOS 系统设置的分组列表，区分通用、偏好、数据与安全、支持与关于。
- 每个设置项统一使用图标、标题和当前状态，减少按钮堆叠；主题保留横向选择卡片，小组件和数据操作保持清晰可见。
- 清空数据继续使用红色危险操作和二次确认，导入 / 导出 / 清空的反馈保持明确。
- 客服入口由微信改为邮箱支持，地址为 `yokinzhu@gmail.com`，点击后直接打开系统邮件。

## 2. 本版实际落地

- 首页候物卡片重排价格、存钱金额、进度条和百分比，并按进度区间着色。
- 新增页改为四步引导流程，减少长表单带来的填写压力，并在保存前集中确认目标价格、已存金额、优先级和分类。
- 新增完全离线的本地提醒，可选择具体日期与时间，并在确认步骤回看提醒设置。
- 提醒通知采用动态模板：高优先级优先提示，接近存满时提示“快存到了”，正文展示存钱进度和分类，并用克制的问题帮助用户再次判断是否值得购买。
- 新增「统计」Tab，提供总预算、已存金额、完成率、状态概览和分类分布。
- 设置页分组容器改为轻量列表风格，客服入口改为邮箱支持。
- 启动页、首页、空状态、首次引导和设置页 slogan 统一为「极简愿望清单与购物清单」。
- 关于 App 版本号、工程构建版本和版本记录同步为 `v1.0.6`。
- 更新工程维护文档中的客服说明，避免继续引导用户使用已经移除的微信客服。

## 3. 验收重点

- 首页不同存钱进度显示对应的灰 / 橙 / 绿颜色，已存满显示蓝灰色。
- 统计页在无数据和有数据时都能正常展示，分类分布不会因空分类崩溃。
- 设置页点击邮箱支持后可唤起邮件客户端，显示收件人为 `yokinzhu@gmail.com`。
- 首次开启提醒时才出现系统权限请求；拒绝权限后可从提示直接进入系统设置。
- 新增或编辑提醒后，系统待处理通知中只保留该候物最新的一条；状态变为已拥有 / 放下或移入回收站后不再提醒。
- 无网络环境下仍可正常创建和触发提醒，App 前台时通知横幅也可显示。
- 设置页仍可正常切换语言、外观、主题，导入 / 导出和清空数据流程不受影响。
- `MARKETING_VERSION`、关于页展示和 Widget 版本号均为 `1.0.6`。
